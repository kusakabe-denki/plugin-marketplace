# 日下部電機 Claude Code プラグイン（plugin-marketplace）

日下部電機の社員が使う Claude Code に、組織設定で配布するプラグインの配布元です。社員が個別にインストールする必要はありません。

## 収録しているプラグイン

| プラグイン | 内容 |
| --- | --- |
| `security-self-check` | 会社のセキュリティルールによる、実行前・実行後の確認（フック H1〜H13）と、秘密情報の置き場所・隠し要素の自己チェック（スキル 2 つ） |

### security-self-check のフック

| ID | いつ | 内容 | 試行（段階1） | 本番（段階2） |
| --- | --- | --- | --- | --- |
| H1 | プロンプト送信前 | マイナンバー・カード番号・「社外秘」・社外の連絡先3件以上 | 注意 | 止める |
| H2 | ツールの実行前 | .env・鍵・証明書・クラウドの認証情報・ブラウザの保存データ・プロセスの環境変数・社外秘フォルダ（書き込み系のツールはパスだけで判定） | 注意 | 止める |
| H3 | ツールの実行前 | メール送信・Teams 投稿・ファイル共有など外部への送信 | なし | 確認 |
| H4 | ツールの実行前 | Cloud Run への直接デプロイ（デプロイ受付の利用を促す） | 注意 | 注意 |
| H5 | 起動時 | プロジェクトの秘密情報の置き場所（1日1回） | お知らせ | お知らせ |
| H6 | ツールの実行前 | クラウド資源の削除・強制 push・履歴の巻き戻し・データベースの削除 | なし | 確認 |
| H7 | ツールの実行前 | 誰でもアクセスできる状態にする公開 | なし | 確認 |
| H8 | 設定の変更時 | 作業中の設定ファイルの変更。本番ではプロジェクトの設定の変更を、実行中のセッションに反映させない（個人の設定は記録だけ） | 記録 | 止める |
| H9 | ツールの実行後・文書を読む前 | 取り込んだ内容（Web・ファイル・コマンド・メール等の MCP）の見えない文字を除き、隠れた指示を Claude と利用者に知らせる。Word・Excel・PowerPoint・PDF の白い文字・極小の文字・非表示のシート／行／スライド・コメント・プロパティ | 注意 | 注意 |
| H10 | ツールの実行前 | 外部への持ち出しの経路（社外への curl・Invoke-WebRequest 等、DNS の問い合わせ、送信する one-liner、データを埋めた URL の WebFetch） | 注意 | 確認 |
| H11 | ツールの実行前 | Claude Code・VS Code の設定・フック・MCP 定義の書き換え | 注意 | 確認 |
| H12 | 起動時 | リポジトリの罠（設定のフック・API の接続先の変更・MCP の定義・VS Code の自動承認や自動タスク・npm install で動く通信・CLAUDE.md や README 等の隠れた指示）。開くたびに調べ、まだ知らせていないものだけ知らせる | お知らせ | お知らせ |
| H13 | 起動時 | 全社プラグインの版の確認。配布元の写し（組織設定の ref で取得済み）より古ければ、`claude plugin update` で自分を更新する（1日1回まで。起動し直すと新しい版で動く）。1日1回、動いている版を管理者の監視画面へ送る | 自動更新 | 自動更新 |

段階と個別の動作は、組織設定の `env` で切り替えます（プラグインの更新は不要）。

- `KUSAKABE_GUARD_STAGE`：`1`（試行・既定）／`2`（本番）
- `KUSAKABE_GUARD_H1`〜`KUSAKABE_GUARD_H13`：`block`（止める）・`ask`（確認）・`warn`（注意）・`on`・`off` で個別に上書き
  - H9 の `block` は、隠れた指示の疑いがある MCP の結果を差し替えて Claude に渡しません
- `KUSAKABE_GUARD_INTERNAL_HOSTS`：H10 で確認しない社内の通信先（`;` 区切り。`*.example.com`・`example.com/org` の形）
- `KUSAKABE_GUARD_REPORT_URL`・`KUSAKABE_GUARD_REPORT_TOKEN`：検知を管理者の監視画面へ送る先と、受け取り専用のトークン（下記）

記録は各 PC の `%LOCALAPPDATA%\ClaudeGuard\` に残ります。

### 検知の送信

H2・H8（止めたとき）・H9〜H12 の検知と、H13 の版の報告（1日1回）は、送信先が組織設定にあれば `outbox.jsonl` に記録し、応答の終わり（Stop・非同期）にまとめて送ります。送るのは日時・利用者（Claude のアカウントのメールアドレス）・PC 名・ルール・動作・ツール名・種類（版の番号）だけで、ファイル・コマンド・結果の中身は送りません。送れなかったときは次回にまとめて送ります。トークンは受け取り専用で、記録を送る以外のことはできません。

### スキル

| スキル | 内容 |
| --- | --- |
| `security-self-check` | プロジェクトの秘密情報の置き場所とリポジトリの罠を一覧にし、会社のルールに沿って直すのを手伝う |
| `hidden-text-check` | 受け取った文書・フォルダの隠し要素（白い文字・非表示のシート・見えない文字・コメント等）と隠れた指示を一覧にする |

## 仕組みと制限

- Windows 標準の PowerShell で動きます（追加のソフトは不要）。速さのため、PowerShell のコマンドレットは使わず .NET の機能だけで書いています（1回あたり約0.3秒）
- フックが失敗しても作業は止めません（`onFailure: continue`）
- 文字列の検査なので完全ではありません。組織設定の拒否ルール・自動モード・デプロイ受付の検査と組み合わせて使います
- H9 の見えない文字の除去は、結果と同じ構造のまま文字だけを除いて渡します（`updatedToolOutput`）。ゼロ幅の文字はメールの余白などに正常に使われるので、除くだけで知らせません。漢字の異体字（1文字）は対象外です
- このリポジトリは公開されています。秘密情報や社内の固有名詞は置きません

## 更新の手順

組織設定の `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` は、プラグインの自動更新も止める。組織設定に `FORCE_AUTOUPDATE_PLUGINS=1` を必ず入れる（自動更新は、最初のメッセージを送ってから最大10分後に動き、起動し直すと新しい版になる）。1.1.1 以降は H13 でもプラグイン自身が更新する。届かない PC は、管理者の監視画面の「全社プラグインの版」で分かる

1. スクリプトを直し、`tests/` のテスト（`py -3 tests/test_hooks.py` と `py -3 tests/test_traps.py`）がすべて通ることを確かめる。`test_traps.py` は罠ファイル（`tests/traps.py`。無害な目印の指示だけを隠したもの）で、隠れた指示・持ち出し・設定の書き換え・リポジトリの罠・検知の送信を確かめる
2. `plugin.json` と `marketplace.json` の `version` を上げてコミットし、同じ番号のタグ（例：`v1.0.1`）を付けて push する
3. 管理画面の組織設定で、配布元の `ref`（2か所）を新しいタグに書き換える
